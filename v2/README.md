# HYPE Advisor **v2** — крипто-ассистент: сканер, скам-фильтр, разбор по запросу

Полностью переработанная архитектура. Старая версия осталась в `src/` и работает
как раньше (`python main.py …`) — v2 живёт рядом и её не трогает.

```
python -m v2 scan                     # трёхуровневый скан рынка
python -m v2 analyze 0x1f9840a85d…    # разбор монеты по адресу контракта
python -m v2 analyze AURORA           # то же по символу
python -m v2 watch                    # фоновый скан по расписанию
python -m v2 serve                    # HTTP-API + мини-дашборд
python -m v2 bot                      # Telegram-бот (нужен TELEGRAM_BOT_TOKEN)
python -m v2 status                   # состояние, метрики, активные фильтры
```

## 1. Быстрый старт

```bash
# 1) зависимости (общие с v1)
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 2) конфигурация (необязательно: без .env бот работает в демо-режиме)
cp v2/.env.example .env

# 3) первый запуск — офлайн, на синтетическом рынке
python -m v2 scan --data-mode demo

# 4) разбор конкретной монеты
python -m v2 analyze AURORA --data-mode demo --deposit 1000
```

Режимы данных (`DATA_MODE` в `.env` или флаг `--data-mode`):

| режим  | что делает |
|--------|------------|
| `auto` | живые провайдеры; если данные не получены — подставляет демо и **помечает это в отчёте** |
| `live` | только живые источники, без подстраховки |
| `demo` | полностью синтетический рынок: работает без сети и без ключей |

Ключи API **никогда не обязательны**. Без `OPENAI_API_KEY` работают rule-based
заглушки, без `X_BEARER_TOKEN` хайп оценивается по рыночным прокси — и то, и
другое явно подписано в отчёте (`⚠️ Эмуляция`, `[без AI]`).

## 3. Трёхуровневый сканер

| уровень | что делает | отсекает |
|---|---|---|
| **L1 — быстрый** | оборот за 5 мин ≥ `$500k`, сделок за 5 мин ≥ `100`, ликвидность, возраст пула, пара к стейблу | мусор, мёртвые пулы, стейблкойны |
| **L2 — скам-фильтр** | топ-10 холдеров ≤ 40%, топ-1 ≤ 25%, LP заблокирована ≥ 80% на ≥ 180 дней, нет `mint()`/`blacklist()`/honeypot, налоги, LP/капа | потенциальные раги и honeypot |
| **L3 — ончейн** | возраст кошелька деплоера ≥ 7 дней, не более 25 задеплоенных контрактов, история транзакций, источник финансирования, `sold_out`/`flagged` | одноразовые и серийные деплоеры |

Порядок «дешёвый → дорогой» экономит запросы: на 150 пулах это ~150 тикерных
проверок, ~40 тройных запросов безопасности и ~10 ончейн-запросов вместо 450
запросов «в лоб».

Отчёт скана показывает **воронку с причинами отсева** — видно не только что
нашлось, но и что именно забраковано:

```
**Уровень 1 — L1 быстрый фильтр:** вошло 14 → прошло **12** (отсеяно 2)
  - объём 5м $91,483 < $500,000 — 1
**Уровень 2 — L2 скам-фильтр:** вошло 12 → прошло **7** (заблокировано 5)
  - Концентрация топ-10 холдеров 62.7% > 40% — 1
  - Есть blacklist() — 1
**Уровень 3 — L3 ончейн-профиль:** вошло 7 → прошло **6** (заблокировано 1)
  - Кошелёк деплоера существует 2.0 дней (< 7) — 1
```

Каждый уровень включается/выключается отдельно (`SCAN_L1_ENABLED`,
`SCAN_L2_ENABLED`, `SCAN_L3_ENABLED`) и имеет собственные подфлаги
(`L2_CHECK_HOLDERS`, `L2_BLOCK_IF_MINTABLE`, …).

### Динамические стоп и цель (вместо фиксированных процентов)

```
стоп = вход ∓ ATR_SL_MULTIPLIER · ATR        (по умолчанию 1.8·ATR)
цель = вход ± ATR_TP_MULTIPLIER · ATR        (по умолчанию 3.6·ATR → R:R 1:2)
объём = (депозит × риск%) / |вход − стоп|    (риск в деньгах фиксирован)
```

Структурный уровень (свинг/фибо) имеет приоритет над формулой, но
только в диапазоне `0.8–3.5·ATR`: слишком близкий стоп выбьет шумом, слишком
далёкий сделает позицию микроскопической. Если при структурном стопе R:R
падает ниже `MIN_RISK_REWARD`, цель уезжает дальше — иначе сделка не
предлагается вовсе.

### Отказоустойчивость

* ретраи с экспоненциальной задержкой и джиттером — только на 429/5xx/таймаутах;
* `CircuitBreaker` на хост: провайдер лёг → не стучимся `CIRCUIT_COOLDOWN_SECONDS`;
* `token-bucket` на хост + глобальный семафор `HTTP_CONCURRENCY`;
* `supervise()` перезапускает упавшую фоновую задачу (WS-поток, цикл скана);
* отказ одного провайдера → раздел помечается `degraded`, отчёт всё равно
  выдаётся, а «уверенность в данных» снижается.

Проверить, что включено прямо сейчас: `python -m v2 status` или `/filters` в боте.

## 6. Торговля

По умолчанию `EXECUTOR_MODE=paper`: бот **не отправляет** ордера на биржу, а
ведёт журнал виртуальных сделок (`data/v2_orders.jsonl`) и закрывает их по
стопам/целям — так уровни из отчётов получают проверяемую статистику.

Живая отправка включается только двумя флагами сразу:

```env
EXECUTOR_MODE=live
EXECUTOR_ALLOW_LIVE=true
BYBIT_API_KEY=...
BYBIT_API_SECRET=...
```

Перед любым ордером работает претрейд-валидация (`Executor.validate`):
вердикт, R:R, проскальзывание, размер позиции, риск. Нарушение — `RiskRejected`,
ордер не создаётся.

## 7. Тесты

```bash
python -m pytest v2/tests -q      # 125 тестов v2
python -m pytest tests -q         # 132 теста v1 (не сломаны)
python -m ruff check v2           # линтер
```

Что покрыто:

* **индикаторы** — кросс-сверка ATR/RSI/ADX/OBV/EMA с эталонной pandas-реализацией из v1;
* **риск-менеджер** — конкретные числа: стоп 1.8·ATR, цель 3.6·ATR, R:R, обрезка позиции по лимиту;
* **три уровня сканера** — каждый фильтр отсекает свой тип скама (mint, LP, холдеры, свежий деплоер);
* **HTTP-слой** — ретраи, circuit breaker, token-bucket, семафор (на `httpx.MockTransport`);
* **отчёт** — первая строка-вердикт, пять обязательных разделов, пояснения к числам;
* **сквозные** — запрос → отчёт, поведение при отказах провайдера.

## 8. Ограничения (честно)

* **Стакан DEX-пула** эмулируется из ликвидности: у DEX нет биржевого стакана.
  В отчёте это помечено. Для токенов с листингом на CEX берётся настоящий стакан Bybit/Binance.
* **Соцфон без `X_BEARER_TOKEN`** — оценка по рыночным прокси, не по твитам. Помечено `⚠️ Эмуляция`.
* **AI без `OPENAI_API_KEY`** — rule-based разбор флагов контракта. Помечено `[без AI]`.
* **Уровень 3 без ключа эксплорера** не выполняется и помечается `degraded`
  (оценка безопасности снижается, токен не блокируется «молча»).
* Отчёты — аналитика, а не финансовая рекомендация.
